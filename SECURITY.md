# Security policy

## Reporting a vulnerability

Please do not open a public issue for a suspected vulnerability or include credentials, private prompts, session logs, or sensitive project data in a report.

Use GitHub's private vulnerability reporting flow:

<https://github.com/bsreeram08/pi-workbench/security/advisories/new>

Include the affected Workbench and Pi versions, operating system, impact, minimal reproduction, and any suggested mitigation. Redact all credentials and personal or proprietary data. The maintainer will acknowledge and triage reports as availability permits.

## Supported versions

Security fixes are applied to the latest release on `main`. Pre-1.0 versions may receive breaking security hardening.

## Trust model

Pi packages and extensions execute code with the permissions of the user running Pi. Review this repository and its pinned submodule before installation.

Important boundaries:

- Coordinator planning keeps native review tickets in memory, bound to the exact saved workflow state. Approval requires a passing native review and interactive confirmation, with authority rechecked under the writer lease. Reload clears pending tickets. Main Pi's planning-only behavior remains agent guidance, not an OS sandbox. Explicit delegation models are checked against the session's available registry and never silently substituted.
- Coordinator execution returns every bounded implementation and independent review to Main Pi. Native completion requires passing review and process evidence, unchanged workspace fingerprints across review and completion, and matching workflow authority under the writer lease. Assessments record Main Pi's reasoning but do not prove semantic correctness. Reload clears pending completion tickets; already completed workflows remain saved.

- Workbench's child-memory guards provide cooperative tool-level isolation; they are not an operating-system sandbox against arbitrary native code or a malicious same-user process.
- Child context includes explicit repository instructions and task-selected installed skills while ambient extension/skill discovery remains disabled. Existing repository instructions and supported references retain a strict 24,000-byte per-file limit. Optional skills allow 32,000 bytes each and 64,000 bytes combined; unavailable or over-budget skills are omitted with a reason, never partially supplied. An invalid higher-priority skill does not trigger fallback to a lower-priority copy. Source paths and skill contents grant no additional tool permissions. See [Child instructions and skills](docs/child-context.md).
- First-party Workbench child agents receive a constructed minimal environment rather than inheriting the parent process environment. Loader hooks, cmux identifiers, GitHub/npm/deployment/cloud credentials, and unrelated provider variables are omitted; each run gets a private synthetic home/tmp directory while Pi authentication remains available through the configured Pi agent directory. Filesystem confinement uses the canonical delegated checkout/worktree independently from the authoritative project key used for memory. File tools are blocked outside that delegated root and from protected Pi/Workbench storage. Bash-capable profiles remain cooperative rather than an operating-system sandbox: command-text checks reduce obvious credential access but cannot stop a malicious interpreter or arbitrary same-user native code. Prefer profiles without Bash for untrusted repositories.
- AgentRunManager's parent protocol is strict LF-delimited JSONL with bounded frames, correlated command responses, sticky protocol/extension failures, an exact pre-prompt active-tool handshake, and `agent_settled` plus exact final-text/session-state handshakes. Inside cmux, a trusted Node stdio bridge preserves that contract while the actual child runs in normal Pi TUI mode; its child channel is a private 0600 authenticated Unix socket with bounded frames. Outside cmux, the headless Pi RPC executor remains a compatibility path. A successful completion requires a non-streaming/non-compacting state with no pending messages and a contained non-symlinked regular checkpoint under a private session directory. Cancellation requests child abort/shutdown before exact-surface cleanup and TERM/KILL escalation, installed before waiting on record persistence. Private integrity-checked run records use unique attempt IDs and detect corruption but are not signatures against a hostile same-user process. Recovery classifies prior nonterminal records as interrupted or orphaned; it does not reconnect to anonymous pipes or assume success.
- Mandatory workflow child results fail closed on cancellation, nonzero exit, or blank output. Every council, workflow, research, and persistent-agent launch surface also fails closed on Pi's project-trust decision before project discovery or child creation; untrusted projects are directed to `/trust` and a Pi restart so children cannot run after project `.pi` resources or packages were omitted. A project-scoped owner-token lease plus a short global update gate and per-canonical-project private writer markers coordinate write-capable entrypoints without serializing independent projects. A long-lived update marker blocks new workflows, and any writer marker blocks an updater before fetch or mutation. This is cooperative same-user coordination rather than an OS sandbox; every live, stale, ambiguous, malformed, or otherwise existing coordination artifact blocks until an operator verifies and deliberately resolves it.
- cmux titles and workspace descriptions receive only a bounded local project/task identity. The derivation strips controls, URLs, code blocks, markup, filler text, common bare credential formats, high-entropy token-like values, and any other secret-, token-, credential-, key-, password-, bearer-, or sentinel-like input; sensitive or empty task input falls back to the project name, while an unsafe project basename falls back to the generic `Project` identity. Final titles and descriptions are bounded by UTF-8 bytes within the bridge contract without splitting Unicode code points. Raw prompts, outputs, questions, model text, credentials, raw errors, and tool names remain excluded. Unknown or model-selected agent roles become `Specialist` and are used only in the bounded description. Lifecycle state never replaces the work identity: completion, failure, cancellation, and needs-attention use notifications/status/progress instead. Other command arguments are exact cmux refs, the project working directory, or private infrastructure paths. Each managed child opens one unfocused terminal tab in the caller's exact workspace/pane. cmux receives one short `bash <private 0700 launcher path>` command; the launcher starts the actual normal Pi TUI with inherited PTY stdio. Task/control traffic uses a private authenticated local socket, not terminal text, process arguments, browser content, HTML, or screen scraping. A private 0600 sidecar carries only categorical native-question state (`waiting` or `running`), never question or answer text; entering `waiting` emits a bounded needs-attention notification rather than changing the title. Exact pane-membership metadata—not cmux's focused-surface fallback—is used for manual-close detection and post-close verification. True normal settlement commits final text/session state before child shutdown and closes only the recorded surface; direct-user abort keeps the tab open, manual closure fails, and bridge signal/parent-disconnect cleanup targets only that surface. AgentRunManager remains lifecycle/result authority, and `cmux-session.ts` remains the owner of ordinary parent completion notifications.
- Workflow `current.json` is the sole authority and is corruption-visible. It is validated and atomically replaced after its plan projection; plan/run artifacts are non-authoritative projections and may be newer after a final authority-write fault. New packet plans persist an independent `verificationMode: "packet"`, so deleting packet state cannot silently restore legacy verification; absence of the mode remains packetless v1 behavior. Present task packets must exactly match the canonical terminal declaration and SHA-256 binding of the complete trimmed approved plan. Packet content is bounded declarative scope and at most 16 acceptance criteria, never executable shell/JavaScript orchestration. Packet verification persists concise allowlisted evidence summaries, categorical protocol failures, and an exact-output digest rather than raw verifier output. Model assessment remains testimony. Completion now additionally requires correlated native check receipts, validated private output artifacts, and matching before/after/final workspace fingerprints. The tool runs literal argv without an implicit shell. An explicitly requested interpreter or project test can still execute arbitrary code; neither check execution nor a zero exit establishes test adequacy or provides an OS sandbox. Git fingerprints exclude ignored files. Non-Git checks use a bounded filesystem snapshot without following symlinks or applying Git ignore rules; broken Git metadata does not trigger this fallback. Both exclude Workbench runtime state; external services and dependencies are not frozen. Malformed JSON, unsafe file kinds/paths, unknown shapes, invalid packet/evidence bindings, and read failures stop the workflow. Confirmation-gated workflow and council actions revalidate an ephemeral in-memory snapshot before launch or persistence; mismatches leave the newer authority untouched and require the user to rerun and reconfirm. Workbench does not automatically recover, replay, resume, create a fresh-context handoff, or maintain a sidecar transaction.
- Recalled memory is untrusted data and cannot override system or user instructions. Consequential claims must be verified against current evidence. Import rejects unknown properties, validates supported versions, checksums, safety filters, bounds, and conflicts before staging, preserves corrupt same-ID local records, and uses a durable visibility barrier during apply; only a Coordinator-approved review can be applied.
- Research features can contact external providers and websites. Review provider terms and avoid sending confidential material.
- Research claims require parent-recorded source artifacts and matching excerpts; model-provided provenance is ignored. User verification is restricted to recorded UI submissions. Audits validate artifact digests and metadata, reject unresolved source states, and separate bibliography references from numeric body claims. This establishes retrieval provenance, not semantic truth, source authority, or OS isolation. Research source snapshots and user observations live in the project research output directory; review them before sharing or committing. Oversized review inputs fail visibly; full semantic coverage and live-model quality are not mechanically guaranteed.
- Automatic trusted-skill evolution is disabled when no explicit configuration exists. `/skills-evolve` and the opinionated installer profile opt into network retrieval from the configured allowlist.
- This repository is a personal Pi profile, not a public `pi install` package. The default installer does not merge personal preferences, companion packages, or skill-evolution settings. `./install.sh --full` is this operator's opinionated machine profile, not the product door. Every successful install transaction records only that explicit `default`/`full` choice for later updater use; legacy values are never guessed. Native check receipts live under the private Pi agent directory and include command arguments and output; treat these artifacts like private session logs. Workbench does not install the separate Receipt runner.
- `/workbench-update` and the optional interactive startup check are confirmation-gated and fail-closed. Startup discovery never applies silently, prompts at most once per candidate per runtime, and fails soft for offline/network/UI/lock/no-update conditions. The updater requires a real clean recursive clone attached to `main`, one exact trusted HTTPS origin, value-validated ordinary branch tracking entries, contained real root and RePrompter Git metadata (absorbed or legacy checkout-local), a valid recorded profile, a successful bounded GitHub Releases response, and linear ancestry. Stable releases win when present; otherwise the explicitly trusted hardcoded `main` ref is a repeatable channel so stale installations can discover later commits. The strict bounded no-follow 0600 categorical audit ledger is validated before main-channel use; malformed, symlinked, non-private, or oversized state blocks. Apply holds the global update marker through completion, reconfirms and revalidates the candidate, fetches only the fixed chosen ref from the trusted URL, permits only the pinned RePrompter submodule mapping, always validates `startup-header.ts` as a candidate blob, validates full or retained exact startup links at runtime, derives rollback classification from immutable old/candidate commits and the candidate gitlink, privately simulates candidate config output, requires every managed live file to equal that simulation after installer success, and verifies a complete same-filesystem checkout snapshot before mutation. Rollback never resets, cleans, force-checks out, or overwrites the checkout: it preserves the whole failed candidate directory and restores the old snapshot through atomic no-replace renames. Deterministic replaced config values are preserved before originals are installed with exclusive no-replace creation; symlink, special-path, and concurrent-value races fail closed without deleting recovery values. Bounded root/RePrompter fingerprints classify ignored credential and runtime-state changes as incomplete rollback; declared rebuildable cache trees are excluded from that classification. Recovery locations remain in the private manifest and never enter audit/UI output; audit records only categorical recovery state. Existing leases are cooperative coordination, not a claim that noncooperating same-user writers can be locked out. Reload occurs only after verified success, existing locks are never taken over, and incomplete rollback never reloads.
- `bun run capabilities:check` is validate-only. It reads only allowlisted capability metadata and compares configured package sources, lock metadata, installed identities, discoverable names, real approved target chains, approved public symlinks, and exclusions. Explicit extension/theme source settings are drift rather than basename-matched aliases. It does not execute packages/extensions, inspect credentials, validate resource syntax/schema, or prove successful loading in an already-running process. Exit status `1` is drift; `2` means inspection failed closed. It has no fix/install/fetch mode.
- `pi-autoresearch` and `@dietrichgebert/ponytail` are hard runtime exclusions in the capability manifest. This does not delete or forbid separately reviewed autoresearch skill documents.

## Secrets

Do not commit `.env` files, Pi authentication state, sessions, memory stores, generated research containing private data, or provider credentials. If a credential appears in a commit, rotate it immediately before rewriting history; rewriting alone does not invalidate it.
